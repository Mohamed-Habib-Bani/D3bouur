# D3BOUUR

An intelligent welcome/receptionist robot — a solo internship project ("Stage") for
**AcaROBOTICS**. It detects a visitor, orients its camera/head toward them, starts a
voice conversation (STT → LLM → TTS), responds vocally, and moves autonomously
(obstacle avoidance, go-to-point, return-to-origin). It also exposes a Wi-Fi remote
control mode and an on-screen kiosk UI (company info, training catalog, events,
contact form).

Full project history, hardware details, and open questions live in
[`CLAUDE.md`](CLAUDE.md) and [`docs/D3BOUUR_Project_Handoff.md`](docs/D3BOUUR_Project_Handoff.md) /
[`docs/D3BOUUR_Phase2_Power_System.md`](docs/D3BOUUR_Phase2_Power_System.md). This file
is just the entry point.

## Status labels used throughout this repo

Every component's README states its status using exactly one of these three labels.
They are not interchangeable, and code should never be described as more finished
than it is:

- **CONFIRMED WORKING** — actually tested with real results (the package's README
  says how/where).
- **BUILT, NOT YET VERIFIED** — code looks complete, but needs real hardware or
  integration testing that hasn't happened yet.
- **NOT STARTED** — stub, placeholder, or genuinely missing.

## Setup

This repo needs to be cloned in **two separate places**, and built differently in
each, because the dev machine and the robot's Raspberry Pi run different OSes:

- your **dev machine** (WSL2/PC) — where you write and test code
- the **Raspberry Pi 5 on the robot** — where the real hardware-facing code
  (camera, ROS 2 nodes talking to sensors, etc.) actually runs

### 1. Dev machine (WSL2/PC — Ubuntu, ROS 2 installed directly)

Prerequisites:
- ROS 2 **Jazzy Jalisco**, sourced (`source /opt/ros/jazzy/setup.bash`)
- Python 3.12+, with each package's own dependencies (see individual READMEs —
  `d3bouur_conversation` and `onvif_camera` in particular need extra `pip install`s)
- [Ollama](https://ollama.com) running locally for `d3bouur_conversation` /
  `d3bouur_behavior` demos

```bash
git clone https://github.com/Mohamed-Habib-Bani/D3bouur.git ros2_ws
cd ros2_ws
source /opt/ros/jazzy/setup.bash
colcon build
source install/setup.bash
```

`build/`, `install/`, and `log/` are gitignored — they're regenerated by
`colcon build` and are never committed.

### 2. The robot's Raspberry Pi (Debian — ROS 2 runs in Docker, not sourced directly)

The Pi runs **Debian**, not Ubuntu, so there's no native Jazzy package for it —
ROS 2 on the Pi runs inside a Docker container (`ros:jazzy-ros-base`), not via a
direct `source /opt/ros/jazzy/setup.bash` like the dev machine above.

```bash
ssh d3bouur@d3bouur.local

# clone the repo on the Pi too — this is a separate clone from your dev machine's
git clone https://github.com/Mohamed-Habib-Bani/D3bouur.git ros2_ws
cd ros2_ws

# build/run inside the ROS 2 Docker container
docker run -it --rm \
  -v "$(pwd)":/ros2_ws \
  -w /ros2_ws \
  ros:jazzy-ros-base \
  bash -c "colcon build && source install/setup.bash && bash"
```

Everything under `src/onvif_camera/` and the Arduino serial bridge assumes it's
running on the Pi, on the same network as the camera and with the Arduino
connected over USB — see those packages' own READMEs for details.

### Arduino firmware — not part of the colcon build

`src/d3bouur_arduino/` is **not** built by colcon or run through Docker — it's
uploaded separately via the Arduino IDE (or `arduino-cli`) directly to the Arduino
UNO. See [`src/d3bouur_arduino/README.md`](src/d3bouur_arduino/README.md) for the
upload steps.

### Running a package

Each package's README has its own "how to run / test this" section. As a starting
point:

```bash
# Behavior state machine demo (needs Ollama running)
python3 src/d3bouur_behavior/demo_state_machine.py

# Conversation brain demo (needs Ollama running)
python3 src/d3bouur_conversation/demo_chat.py

# Kiosk web UI
python3 src/d3bouur_interface/run_server.py
```
